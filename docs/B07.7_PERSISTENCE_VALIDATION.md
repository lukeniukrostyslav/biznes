# B07.7 — Persistence Validation Checkpoint

Дата: 2026-09-24

## Цель

Усилить защиту local-first store перед дальнейшим расширением функциональности. Проверка должна ловить повреждённые или противоречивые записи до того, как они попадут в расчёты и UI.

## Реализовано

`src/core/persistence.js` теперь дополнительно проверяет:

- обязательный строковый `id` у каждой записи;
- дублирующиеся ID внутри одной коллекции;
- корректность типов записей;
- конечные неотрицательные значения для основных денежных полей;
- `quantity` и `unitPrice` invoice line items;
- существующие relationship integrity checks остаются без изменений.

## Почему это важно

BUSINESS OS является local-first приложением. Пользовательские данные могут приходить не только из текущего UI, но и через импорт JSON. Поэтому relationship validation недостаточно: повреждённое денежное значение или дублированный ID могут привести к некорректным финансовым расчётам.

## Тест

Добавлен regression test в `src/core/persistence.test.js` для:

- duplicate ID;
- отрицательного invoice amount;
- нечислового line-item unit price.

## Verification

Код и тест изменены и сохранены в GitHub.

Полный `npm test` в текущем execution environment не был запущен: среда не имеет сетевого доступа для клонирования репозитория. Поэтому этот checkpoint не утверждает, что весь test suite прошёл.

Следующий шаг — выполнить реальный test/browser verification в доступной execution environment, затем продолжить B07.
