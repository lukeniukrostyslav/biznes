## Решение для BUSINESS OS

Наша дифференциация должна быть уже следующего уровня:

1. **Profit-first:** прибыль и margin являются первоклассными объектами, а не отчётом в конце.
2. **Local-first:** бизнес-данные остаются локально в core-продукте.
3. **One-time:** отсутствие обязательной подписки.
4. **Real application:** не Notion-шаблон.
5. **Action-first dashboard:** каждый KPI ведёт к следующему действию.
6. **Connected data:** Lead/Client/Proposal/Project/Invoice/Payment используют единую модель.
7. **Mobile parity:** мобильная версия сохраняет ключевые финансовые действия.

## Ограничение

### Решение для следующего этапа

Следующий приоритет BUSINESS OS — не добавление ещё одного модуля, а **единый жизненный цикл записи**: создание → редактирование → связь с другими сущностями → финансовое влияние → удаление/архивация. После этого финансовый engine должен получать данные UI, а dashboard — рассчитываться из store, а не из демонстрационных значений.
